# v0.3e Log4OM — build hotfix manifest

Data: 2026-09-20

## Diagnoza

Po v0.3d kompilacja przeszła problem `wsprd_jtdx` i doszła dalej. Następna awaria miała ten sam charakter, ale dotyczyła targetu C++ linkującego statyczną bibliotekę `libwsjt_fort.a`.

Widoczne brakujące symbole GNU Fortran obejmują m.in.:
- `_gfortran_st_write`
- `_gfortran_transfer_character_write`
- `_gfortran_st_write_done`
- `_gfortran_runtime_error_at`

## Poprawka

Na `MINGW + GNU Fortran`:
- `wsjt_fort` otrzymuje `PUBLIC gfortran`
- `wsjt_fort_omp` otrzymuje `PUBLIC gfortran`
- `wsprd_jtdx` zachowuje bezpośredni link do `gfortran`, bo zawiera surowe obiekty Fortrana zamiast linkować `wsjt_fort`

Dzięki PUBLIC zależności każdy target C++ korzystający z bibliotek Fortrana dostaje `-lgfortran` automatycznie.

## Dodatkowe gate

Przed pełnym buildem builder wymaga `-lgfortran` w grafie komend:
- `wsprd_jtdx`
- `jtdx`
- `jtdxjt9`

## Zakres

Zmiana dotyczy wyłącznie toolchain/linkera. Nie zmienia logiki FT8, FT2, SuperHound, Log4OM, CAT/PTT, GUI, WideGraph ani Slice Mastera.
