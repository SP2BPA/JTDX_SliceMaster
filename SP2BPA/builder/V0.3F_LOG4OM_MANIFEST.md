# v0.3f Log4OM — CMake link-signature hotfix

Data: 2026-09-20

## Błąd v0.3e

CMake zatrzymał konfigurację na:
- `wsjt_fort`
- `wsjt_fort_omp`

Komunikat: plain signature `target_link_libraries` była już wcześniej użyta, a późniejsze wywołanie użyło formy keyword `PUBLIC`.

## Przyczyna

Bazowy JTDX 2.2.159 używa:
`target_link_libraries (wsjt_fort ${FFTW3_LIBRARIES})`

oraz analogicznej plain formy dla `wsjt_fort_omp`.

v0.3e dodał:
`target_link_libraries (wsjt_fort PUBLIC gfortran)`

CMake wymaga jednej formy składni dla danego targetu.

## Poprawka v0.3f

Pozostaje jedna, zgodna forma:
`target_link_libraries (wsjt_fort gfortran)`
`target_link_libraries (wsjt_fort_omp gfortran)`

W plain signature zależności pozostają w link interface tego projektu, więc konsumenci C++ dostają `-lgfortran`.

Pre-build gate nadal wymaga `-lgfortran` dla:
- `wsprd_jtdx`
- `jtdx`
- `jtdxjt9`

## Zakres

Wyłącznie zgodność CMake/build. Bez zmian w FT8, FT2, SuperHound, Log4OM runtime, CAT/PTT, WideGraph, GUI i Slice Master.
