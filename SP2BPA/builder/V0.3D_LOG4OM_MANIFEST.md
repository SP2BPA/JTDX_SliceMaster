# v0.3d Log4OM — build hotfix manifest

Data: 2026-09-20

## Diagnoza z pełnego logu v0.3c

- CMake zakończył konfigurację poprawnie.
- Źródłowe gate Log4OM, QtSql, qsqlite, Hamlib i FFTW przeszły.
- Build doszedł do **1037/1219**.
- Awaria wystąpiła przy `Linking CXX executable wsprd_jtdx.exe`.
- Link wykonywał `c++.exe`.
- W komendzie były obiekty Fortrana: `indexx.f90.obj` i `osdwspr.f90.obj`.
- Komenda nie zawierała `-lgfortran`.
- Linker zgłaszał brak symboli:
  - `_gfortran_runtime_error_at`
  - `_gfortran_stop_string`
  - `_gfortran_cshift0_4`

## Poprawka v0.3d

Wyłącznie na `MINGW + GNU Fortran` target `wsprd_jtdx` otrzymuje jawne:

`target_link_libraries (wsprd_jtdx gfortran)`

Builder po konfiguracji CMake uruchamia kontrolę komendy Ninja dla `wsprd_jtdx` i wymaga obecności `-lgfortran` **przed** pełną kompilacją.

## Zakres

To jest poprawka toolchain/build-only. Nie zmienia:
- FT8 / FT2,
- SuperHound,
- dekodera/DSP,
- Log4OM runtime logic,
- CAT/PTT,
- WideGraph/GUI,
- Slice Master ani sterowania wzmacniaczem.
